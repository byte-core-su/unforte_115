🚨 Phase 0：危機發布與系統診斷

💥 基地遭重創！防禦系統啟動太慢？

「警報！密集隕石群逼近！」剛才測試時，指揮官按下啟動鍵，畫面竟跳出對話框：
💬 「請輸入要畫正幾邊形？」、「請輸入要幾個圖形？」
就在指揮官慌忙打字輸入的幾秒鐘，隕石已經無情地砸中了基地！我們發現了系統的致命漏洞：「互動式提問」太耗時了！ 在分秒必爭的危機中，根本沒時間手動輸入參數。

🛠️ 核心概念實作

捨棄耗時的「詢問」積木，改用預先寫好的參數變數與雙層陣列迴圈，讓程式一鍵瞬間啟動全自動防禦網。

🧠 運算邏輯梳理

重新規劃「環繞地球」的雙層防禦陣列，精準計算圖形的邊數與旋轉角度，確保防護網交織且毫無死角。

🛡️ 能量防護網強度

防護網不能只有形狀，還需要足夠的厚度！加入「筆跡寬度」積木設定，確保防禦網有足夠的能量強度來抵擋高能隕石的貫穿。

Phase 1: 創造 (Creation) —— 代碼優化與防禦網重構

🧠 運算邏輯梳理

規定先不碰鍵盤，請工程師們先在紙上或腦中進行「畫流程圖」的自我推演：

  • 如何把舊程式的「詢問與等待」拿掉？
  • 如何改由程式內部直接給予變數數值（將 Input 從手動輸入改為宣告常數），讓防禦網能「一鍵瞬間啟動」？

🛠️ 核心概念實作

想通了邏輯後，請動手修改下方的主程式碼。我們必須：

  1. 刪除「詢問」積木。
  2. 加上「筆跡寬度設為 ( )」積木，設定防禦網的強度。
  3. 改用「變數設定」積木，保持空白讓大家自己決定「正幾邊形」與「幾個圖形」的常數。
  4. 一鍵呼叫函式並佈署。

Phase 2: 分析 (Analysis) —— 防禦強度與參數盲測

防禦參數盲測：程式碼重構完成後，防禦網已能瞬間啟動。請開始進行「數字組合實驗」，直接在變數欄修改數字，測試不同的「正幾邊形」與「幾個圖形」，觀察動態隕石是否會穿透孔洞。

防禦網強度測試：想一想：「如果防禦網太薄，會發生什麼情況？」請在下方測試不同的強度，並將「筆跡寬度」參數加大，體會強度對防禦效果的關鍵影響。

Phase 3: 反思 (Reflection) —— 資源最佳化與生活對接

⚖️ 效能最佳化思辨

🤔 指揮官的靈魂拷問： 「如果設定畫 100 個圖形，防禦網絕對最密最安全，但程式運作會變慢。如果筆跡無限加粗，雖然絕對貫不穿，但系統能量負荷極大。身為工程師，你的責任是找出能過關的最少資源，還是不計代價開到最大？」

🎯 最佳化挑戰： 請回到上方的控制面板，找出「剛剛好能擋住隕石」的最優化變數組合（例如：最少的圖形數量、適中的寬度），學習在「絕對安全」與「系統資源」間做出權衡！

🌍 現實生活對接

在現實生活中，我們剛剛測試的「陣列排列覆蓋」與「護盾寬度（厚度）測試」，其實正運用在這些領域：

  • 📶
    基地台訊號無死角覆蓋網 如何用最少的幾何排列（如蜂巢狀六邊形），達成訊號不漏接的全面覆蓋？
  • 🛡️
    裝甲車的防護鋼板厚度計算 如同調整筆跡寬度，工程師必須在「防禦強度」與「車體重量（機動性/耗能）」之間取得完美平衡！
